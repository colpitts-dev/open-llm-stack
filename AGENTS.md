## Principles

- **Light.** One compose file, one network, one `.env`, one Makefile. Do not add a service, a network, a build step or a dependency the spec does not name. The one build is `agents/goose/Dockerfile` (opt-in goose runtime, plan 12).
- **Every layer optional and swappable.** Profiles switch layers off; `*_URL` variables point at external instances. Never add `depends_on` across profiles — Compose rejects the whole project when the target profile is off (verified; spec §4.3).
- **Out of the box.** `make init && make up && make test` must pass on the reference host with zero edits. Every secret is generated by `scripts/init.sh`; nothing is hand-pasted.
- **Loopback only.** Every published port uses `${BIND_HOST:-127.0.0.1}`.
- **Pin and verify.** Exact image tags only, each recorded in spec §1 with its verification date. You have no internet: do not change a tag. If a pinned image fails, report it; do not guess another tag.
- **A claim that something works means it was run.** Bring the stack up, curl it, exec into it, show the output. Paste real output into the plan's execution report.
- **Comments only for the non-obvious why** (a verified gotcha, a security tradeoff). Match the density in `docker-compose.yml`.
- **Open weights only** in `proxy/config.yaml`: never register a closed-weight model or a pass-through router.

## Non-negotiable facts (each verified live on 2026-09-12; details in docs/spec.md §5)

- The Buzz relay binds one community to the exact `host:port` in `RELAY_URL` (`BUZZ_PUBLIC_HOST`). Any other `Host` header gets 404. `localhost:3002` ≠ `127.0.0.1:3002`. The `buzz-agent` therefore runs with `network_mode: host`.
- The relay's browser bundle is a repo browser + invite pages, not a chat client; chat is the desktop app or the `buzz` CLI.
- Open WebUI no-login mode still needs a bearer token for API calls: `POST /api/v1/auths/signin` with empty email/password returns it. `ENABLE_PERSISTENT_CONFIG=false` keeps env authoritative.
- LiteLLM image has no curl (healthcheck uses python3). Ollama image has none either.
- Scores are Jared's (coordinator and judge; no separate judge agent), computed by `agents/bin/score-post` from a fixed rubric (spec §5.14); never gate a merge on them; agents never see the formula; effort is not evidence; the host scripts use the judge's token because the admin token has no `read:issue`.
- Runtimes are switched per member (`runtime = "goose"` in `teams/<team>/team.toml`, `make member-runtime N=<name> R=goose|buzz-agent`; `make dinesh-runtime` is the plan 12 alias); closed-weight runtimes (`claude-agent-acp`) are never a default and need their own opt-in plan (spec §5.13).
- Progress posts come from the two persona milestones (`🚩 pushed …`, `🚩 CI …`) and, opt-in, `scripts/team-narrate.sh` in the entrypoint (`TEAM_NARRATE`, spec §5.12). Never add a persona loop that narrates every step; never put @mentions or bold on progress lines (they mark deliverables); the model's shell tool cannot post progress (scrubbed env).
- Agents create repositories only through `agents/bin/new-repo` (template + self-demotion); no agent is ever a repo admin or org owner; roles are Gitea teams (`builders`, `reviewers`, `coordinators`), not persona text (spec §5.11).
- The team works against the bundled Gitea or an external one by `.env` alone (spec §5.10): the bootstrap is API-only, agent tokens are minted with each agent's own password, a private CA reaches the agents via `GITEA_CA_FILE` (env vars set only when the mounted file is non-empty). Inside a CI job on an external instance Gitea is `http://gitea:3000`-style internal, never the public name; the template clones from `GITHUB_SERVER_URL`. Never register the bundled `gitea-runner` against an external instance.
- MinIO images come from quay.io; Docker Hub denies anonymous pulls of `minio/*`.
- The reference host runs Ollama at `0.0.0.0:11434` outside this project; ports 3000–3003 must be free before `make up` (`scripts/check-ports.sh`).
- Members exist only in `teams/<team>/team.toml`; `teams/<team>/compose.yml` is generated (`make team-render`) and never edited; scripts find agents by role through `scripts/team-roster.py`, never by name; roles are the closed list in `agents/roles/` mapped to forge teams (spec §5.17).
- Every chat model declares `context_window`; `max_input_tokens = context_window − max_output_tokens − max(context_window/4, 8192)`; Ollama entries mirror it as `num_ctx` and carry `keep_alive`; `make context-probe` must pass after any registry edit; the smoke fails on the arithmetic (spec §5.15). Never raise a window by hand: `make model-fit` (Ollama) or the server's flags plus the probe.
- The stack's energy is measured on the host by `make power-meter` (probes `nvml`, `hwmon`; each row carries a domain and a scope `gpu|soc|host`; scopes are never summed), reported in kWh first (`make cost-report`: total, then model, client, domain), attributed to LiteLLM's ledger for one scope (`POWER_SCOPE`) and priced from `.env` (`POWER_COST_PER_KWH` in cents, printed as dollars); `measured_kwh` and `host_kwh` are never blended and the report says whether the host figure is measured or estimated (`POWER_HOST_OVERHEAD`, additive watts, never a factor); idle is shown, never charged to a client (spec §5.16).

## Development commands

```bash
make init             # ./scripts/init.sh: .env + secrets + proxy/config.yaml (idempotent)
make up               # ./scripts/check-ports.sh; docker compose up -d --wait; ./scripts/preflight.sh
make down             # docker compose down (volumes kept)
make ps               # docker compose ps
make logs S=<service> # docker compose logs -f <service>
make test             # ./scripts/smoke-test.sh: one section per profile in COMPOSE_PROFILES
make reload           # docker compose restart litellm, after editing proxy/config.yaml
make gitea-bootstrap  # ./scripts/bootstrap-gitea.sh: admin user + API token into .env
make team-bootstrap   # ./scripts/bootstrap-team.sh: agents' Gitea users + tokens, runner token, fixture repo demo-calc (plan 08)
make team-smoke       # ./scripts/team-smoke.sh: job thread -> Dinesh PR -> green CI -> Gilfoyle review (profile team; make test runs it too)
make team-model M=<model>   # switch the team's model (checked against LiteLLM): edits team.toml, re-renders, recreates every member; caps come from the registry
make team-render [T=<team>] # scripts/team-render.py: teams/<team>/team.toml -> teams/<team>/compose.yml + .env lines, mints missing member keys (plan 16; make init runs it)
make litellm-keys     # scripts/litellm-keys.sh: one LiteLLM virtual key per member, Open WebUI and the Buzz agent into .env (plan 16; team-bootstrap runs it)
make team-status      # members, roles, logins, container state from the roster
make member-add N=<name> R=<role> [TITLE="…"]   # append to team.toml, stub persona, render, bootstrap forge user + token + team + LiteLLM key, start it
make member-rm N=<name> [PURGE=1]               # stop, remove from team.toml and forge teams, re-render; PURGE=1 deletes forge user + volume
make member-runtime N=<name> R=goose|buzz-agent  # per-member runtime switch (plan 12 knob; make dinesh-runtime R= is its alias)
make team-new T=<name> FROM=<preset>             # start a team from teams/_presets/ (dev-squad|solo-builder|review-board|content-studio)
./scripts/buzz-smoke.sh   # mention the bundled agent, expect a reply (profile buzz-agent; make test runs it too)
make power-meter      # energy meter, 1 row/s per domain into litellm-db (plan 15; probes from POWER_PROBES; foreground)
make cost-report [SINCE="24 hours"]   # kWh the local models burned and what it cost, then per model, client, domain
```

## Executing a plan

1. Read `docs/spec.md` sections the plan cites, then the plan, fully, before touching a file.
2. Create files with the exact contents given; do not "improve" flags, tags, paths or env names — each was verified. If something in the plan is wrong, fix it, and write what you changed and why in the plan's execution report.
3. Run every validation command, in order, against the live stack. Show real output. A gate that "should pass" did not pass.
4. Leave the stack running and `.env` valid when you finish. Never commit `.env`, `proxy/config.yaml`, or anything under `models/`.
5. Update this file's status line when a plan is done.
