## Buzz Desktop (0.5.32) managed agents — where config really comes from

- App data: `~/.local/share/xyz.block.buzz.app/agents/` — `managed-agents.json` (records), `global-agent-config.json` (0600; `{env_vars, provider, model, preferred_runtime}`; live-resolved at spawn → restart the agent to apply), `agent-pids/`, `logs/<pubkey>__*.log`, `teams.json`. Relay URL is remembered in localstorage; no launch env needed.
- Precedence (low→high): baked build env < global file < persona definition (linked) / instance (definition-less) < Buzz identity. A linked instance (persona_id set, e.g. builtin:honey) takes `system_prompt` and provider/model from the PERSONA DEFINITION; edits to the instance's fields are ignored. Team "instructions" apply to every deployed member.
- Provider values: `openai` (label "OpenAI Runtime API Key" → `OPENAI_COMPAT_API_KEY`), `openai-compat`, `anthropic`, `openrouter`, `databricks*`. For LiteLLM: provider `openai`, model = registry name, env `OPENAI_COMPAT_BASE_URL=http://127.0.0.1:3000/v1`, `OPENAI_COMPAT_API=chat`, key = LITELLM_MASTER_KEY. Unset provider/model → agent runs in "setup mode" and posts a config nudge instead of answering.
- Reserved env keys (rejected from user env): BUZZ_PRIVATE_KEY, BUZZ_RELAY_URL, BUZZ_AUTH_TAG, BUZZ_API_TOKEN, BUZZ_ACP_AGENT_COMMAND/ARGS/MCP_COMMAND, BUZZ_ACP_AGENTS, BUZZ_ACP_RESPOND_TO*, BUZZ_ACP_AGENT_OWNER, BUZZ_ACP_DISPLAY_NAME, BUZZ_ACP_SESSION_POLICY, … Derived keys rejected in global env: GOOSE_PROVIDER/MODEL, BUZZ_AGENT_PROVIDER/MODEL. `BUZZ_ACP_SYSTEM_PROMPT` and `BUZZ_AGENT_REQUIRE_REPLY` are allowed but the app overwrites the system prompt from the persona.
- Parallelism: instance field `record.parallelism` → `BUZZ_ACP_AGENTS` (Edit Agent → Advanced; app default 10). Persona-level parallelism is a template default only.
- App agents get `BUZZ_ACP_RESPOND_TO=owner-only` + NIP-OA `BUZZ_AUTH_TAG`; shell tool calls prompt the user (allow once/always) → unattended posting needs "always allow".
- App-bundled binaries: `/tmp/.mount_Buzz_*/usr/bin/{buzz-acp,buzz-agent,buzz-dev-mcp,buzz}`; `/proc/<pid>/environ` of `buzz-acp` shows the effective config.
- Import: persona packs are NOT importable; only `.agent.json`/`.team.json` snapshots. Use `buzz pack inspect` to read a pack and recreate by hand.
