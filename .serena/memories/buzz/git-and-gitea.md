## Git: relay-hosted vs Gitea (verified in source 2026-09-13)

- Relay git: smart HTTP at `<relay>/git/<owner>/<repo>`, NIP-98 auth via `git-credential-nostr` (sprig entrypoint scopes it to the relay URL), commits signable via `git-sign-nostr`. Repos announced as NIP-34 `kind:30617` (`buzz repos create --id … --channel <uuid>`; the `buzz-channel` tag IS the ACL — without it the relay 404s clone/push). Refs on object storage (MinIO) with CAS manifests.
- CLI surface in the pinned sprig image: `buzz repos create/get/list`, `buzz pr open/update/get/list/status` (NIP-34 kind:1618; needs `--commit --clone`, `--channel` for provenance), `buzz issues create/…` (kind:1621; infers repo from a project home channel), `buzz projects create/add-repo/add-channel` (NIP-MP kind:30621), `buzz workflows create --yaml`, `buzz agents draft-create` (owner-reviewed agent creation from chat). PR/issue/repo/project commands return a `buzz://` `link` to post verbatim.
- Desktop Projects: "a project starts as a channel with a repository"; Add repository takes a clone URL BUT `validate_workspace_clone_url` requires the active relay's scheme/host/port → Gitea/GitHub repos cannot be attached; in-app diffs, branches, PR review timeline only work for relay-hosted repos (the app runs `git` locally against the relay).
- Forge status (VISION_PROJECTS + ARCHITECTURE known limitations): git hosting ✅, workflows ✅ (triggers: message_posted/reaction_added/schedule/webhook; actions: send_message, add_reaction, call_webhook, delay, request_approval ⚠ not resumable, send_dm/set_channel_topic stubbed), approval gates 🚧, merge coordinator 📋, no CI runner ("agents perform the compute").
- Gitea: bundled 1.27.3, HTTP only, token auth; Gitea Actions (needs an `act_runner` service — not in the stack yet) + branch protection = external validation that ships today.
- Recommended split (decision pending plan 08): Gitea = system of record + CI + merge; Buzz = request/coordinate/report (channel per repo, thread per job, PR URL posted as plain text). Revisit relay-hosted git when approval gates/merge coordinator land.
- Agents pushing to Gitea: token via git credential helper in the container (never in prompts), branch `agent/<thread>`, PR via Gitea API (curl), `@mention` the requester with the URL.
